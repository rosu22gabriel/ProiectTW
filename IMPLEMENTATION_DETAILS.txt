DETALII_IMPLEMENTARE (versiune detaliata)

1) ARHITECTURA GENERALA
- Aplicatia este impartita in doua module:
  - back-end: API REST in Node.js + Express + Sequelize
  - front-end: SPA React (Vite) cu React Router
- Comunicarea front-end ↔ back-end se face prin HTTP/JSON.
- Autentificarea este cu JWT. Token-ul este salvat in localStorage si trimis in header Authorization: Bearer <token>.
- Datele sunt stocate in MySQL. Sequelize gestioneaza modelele, relatiile si query-urile.
- Continutul notelor este text (markdown), iar atasamentele sunt stocate ca BLOB (binar) in DB.
- Integrare externa: backend are endpoint pentru rezumate Wikipedia (summary) si frontend poate importa textul in editor.

4) MODELE & RELATII

- passwordHash
- role (owner/editor/reader)

4.2) Note
Fisier: back-end/models/notes-model.js
Campuri:
- noteId (PK)
- title
- content (TEXT long)
- userId (FK, autor)
- subjectId (FK, optional)

4.3) Subject
Fisier: back-end/models/subjects-model.js
Campuri:
- subjectId (PK)
- name
- description

4.4) Tag
Fisier: back-end/models/tags-model.js
Campuri:
- tagId (PK)
- name

4.5) Group
Fisier: back-end/models/groups-model.js
Campuri:
- groupId (PK)
- ownerId (FK user)
- name

4.6) Attachment
Fisier: back-end/models/attachments-model.js
Campuri:
- attachmentId (PK)
- filename
- mimeType
- data (BLOB)
- noteId (FK)

4.7) GroupInvite
Fisier: back-end/models/group-invites-model.js
Campuri:
- inviteId (PK)
- groupId
- invitedUserId
- invitedByUserId
- status (pending/accepted/declined)

4.8) Asociatii (back-end/models/associations)
- Users ↔ Notes
  - user hasMany notes (author)
  - note belongsTo user (author)
  - user belongsToMany notes (shared) via sharedNote
- Notes ↔ Tags
  - many-to-many via noteTags
- Subjects ↔ Notes
  - subject hasMany notes
  - note belongsTo subject
- Notes ↔ Attachments
  - note hasMany attachments
  - attachment belongsTo note
- Users ↔ Groups
  - user hasMany groups (ownedGroups)
  - group belongsTo user (owner)
  - user belongsToMany groups (members) via groupMembers
  - group belongsToMany users (members) via groupMembers
- GroupInvites
  - group hasMany invites
  - invite belongsTo group
  - user hasMany invites (invitedUser)
  - user hasMany sentInvites (invitedBy)

5) AUTENTIFICARE & SECURITATE
5.1) JWT
Fisier: back-end/middlewares/auth.js
- requireAuth verifica token-ul Bearer, decodeaza JWT si pune req.user.

5.2) Auth controller
Fisier: back-end/controllers/auth-controller.js
- POST /api/auth/register:
  - verifica username, email, password
  - email trebuie @stud.ase.ro
  - parola e hashuita cu bcrypt
- POST /api/auth/login:
  - valideaza credentialele
  - returneaza token JWT
- GET /api/auth/me:
  - returneaza profilul utilizatorului curent

5.3) CORS
- In server.js, CORS permite origin: http://localhost:5173

10) INTREBARI (RASPUNSURI)
- Delete
  - Se foloseste metoda HTTP DELETE pe endpoint-urile REST (ex: /api/notes/:id, /api/groups/:id).
  - In backend, stergerea se face prin Sequelize .destroy() (functie deleteElement in db-utils.js).
- Method stergere backend
  - Express + Sequelize: DELETE route -> controller -> deleteElement -> model.destroy().
- Ce backend am folosit (si middleware? daca e cazul)
  - Backend: Node.js + Express.
  - Middleware: express.json, cors, auth (JWT), validation (campuri obligatorii), dotenv.
- Axios
  - Nu. Clientul HTTP in front-end este fetch (front-end/src/api.js).
- Sequelize
  - Da, Sequelize este folosit pentru modele, relatii si query-uri.
- Orm
  - ORM: Sequelize.
- Hashing la parola
  - bcryptjs (bcrypt.hash).
- Encriptare
  - Parolele sunt hash-uite (nu sunt stocate in clar).
  - Tokenurile JWT sunt semnate cu JWT_SECRET.
- De cate ori e encriptat
  - bcryptjs foloseste 10 salt rounds (cost factor 10).
- Biblioteci de autentificare
  - jsonwebtoken pentru JWT.
  - bcryptjs pentru hash parola.
- Package json
  - back-end/package.json si front-end/package.json (dependente separate).
- Front ce am folosit
  - React + Vite + react-router-dom.
  - Editor markdown: @uiw/react-md-editor.
